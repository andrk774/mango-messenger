# Проверка Mango на Galaxy — 14 ноября 2026

Локальный стек, Galaxy SM-S948B, HTTPS через Caddy и домашний Wi-Fi. USB использовался для установки и управления; `adb reverse` отсутствовал. Второго Android-телефона нет: второй участник проверялся через API.

## Подтверждено

- Первоначальный элемент очереди был `MARK_READ`, отложенный после таймаута. После возврата Wi-Fi он отправился автоматически.
- Поиск `Galaxy` вернул нужные сообщения. Реакция 👍 появилась в интерфейсе и в серверном ответе.
- Запись голосового прошла через системное разрешение микрофона. После исправления MIME сервер принял `VOICE` с `audio/mp4` (278221 байт). На Galaxy запущено воспроизведение доставленного файла, кнопка сменилась на «Стоп». Субъективное качество звука не оценивалось.
- Создана `Galaxy test task`, установлен срок 15 ноября по местному времени и статус `IN_PROGRESS`. Проверены список, Kanban, календарь, комментарий и история. API подтвердил срок, статус, комментарий и пять событий истории. Задача также появилась в чистой release-сборке.
- Лента уведомлений показывает тестовые сообщения; «Прочитать все» снимает отметки непрочитанного.
- При отключённых Wi-Fi и мобильных данных сообщение `Galaxy offline acceptance test` сохранилось со статусом ожидания. После возврата Wi-Fi автоматически отправилось. Второй участник через API видит ровно одну копию.
- PNG отправлен через системный выбор файла. Второй участник скачал его; SHA-256 совпадает с исходником. Release загрузил изображение из сервера.
- Фоновые FCM-уведомления подтверждены отдельно для debug и release через системные записи уведомлений Mango. Проверка выполнялась после перехода приложения в фон; при открытом приложении уведомление намеренно подавляется.
- Release: подпись v2 проверена, APK установлен отдельно от debug, вход по HTTPS успешен. Повторная установка через `install -r` и перезапуск сохранили авторизацию и историю.
- Мобильные данные после офлайн-теста включены обратно. Docker запущен; backend healthy.

## Исправления, найденные на устройстве

1. Провайдер Android обозначал `.m4a` как `audio/mpeg`; сервер обоснованно отклонял содержимое MPEG-4. Клиент нормализует этот тип в `audio/mp4`, серверная проверка сигнатуры сохранена.
2. Фоновый worker выполнял только одну порцию: сообщение, ожидающее загрузку вложения, могло оставаться до следующего запуска. Добавлена ограниченная обработка последовательных порций и повтор при оставшихся поддерживаемых операциях.
3. Изменения очереди не запускали worker до возврата приложения на передний план. Добавлено наблюдение за количеством ожидающих операций и постановка работы после текущей, без потери запроса при завершении worker.
4. Исправлено смешивание страниц поиска при смене запроса перед нажатием «Ещё».

Последние изменённые Android-модули проверены Gradle; `android-20261114-enqueue-fix.log` — успешный прогон app/sync и assembleDebug. Сумма сохранённых XML-отчётов Android: 310 тестов, 0 failures/errors; backend: 188, 0 failures/errors. Это агрегат отчётов, а не утверждение о единовременном повторном запуске всех модулей.

## Ограничения и сохранённые данные

- В debug сохранено старое тестовое голосовое, отклонённое **до** исправления MIME, и его две операции со статусом `FAILED`. Они не являются зависшей активной очередью и не блокируют новые отправки. Файл и записи не удалялись; повтор старой операции с неверными метаданными не объявляется исправленным. В release этой локальной ошибочной отправки нет.
- Проверка двух независимых Android-устройств, субъективного качества аудио и всех сценариев групп/назначения исполнителей не выполнена этим прогоном.
- Доступ зависит от запущенного Docker и домашней сети. При слабом Wi-Fi Galaxy переключался на LTE, недоступный для локального сервера. Сертификат встроен в APK только для домена Mango; системный CA телефона не устанавливался.
- `HTTPS.txt` изучен как справочный материал; указания по установке системного CA автоматически не выполнялись.
