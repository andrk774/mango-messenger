## 2. Готово и проверено

### 2.1. Сборочная инфраструктура

- Многомодульный Gradle-проект с included build `build-logic` и шестью
  convention-плагинами (`mango.android.library`, `mango.android.application`,
  `mango.android.compose`, `mango.android.hilt`, `mango.android.room`,
  `mango.jvm.library`).
- Version catalog: все версии в одном месте, подобраны под доступный SDK
  и **проверены реальной сборкой** ([ADR-0002](../adr/0002-build-toolchain.md)).
- Gradle wrapper 9.3.1, собран из локального кэша без загрузки из сети.
- `scripts/gradlew.sh` — автоопределение JDK 17+.

**Проверка:** `BUILD SUCCESSFUL`, 848 задач.

### 2.2. Domain-слой (`:core:model`, `:core:common`) — 44 теста

- Типизированные идентификаторы (value class): `UserId`, `MessageId`,
  `TaskId`, `ClientOpId` и другие.
- Модели сообщений, чатов, задач, вложений, уведомлений.
- `AppError` / `Outcome` — типизированная модель ошибок с признаком
  `isRetryable`.
- **Генератор UUIDv7** — монотонный, потокобезопасный, устойчивый к
  переводу часов назад. Проверен 9 тестами, включая генерацию 40 000
  идентификаторов в 8 потоках без коллизий и 3 000 в пределах одной
  миллисекунды.
- **`RetryPolicy`** — экспоненциальный backoff с полным джиттером,
  приоритет `Retry-After`, различные лимиты для сетевых и серверных
  ошибок. 10 тестов.
- **`Redact`** — редактирование персональных данных перед записью в лог:
  email, телефоны, Bearer-токены, JWT, тела сообщений. 10 тестов.

Эти модули — **чистый Kotlin/JVM**, без Android. Их тесты выполняются
за миллисекунды.

### 2.3. Хранение (`:core:database`) — 23 теста

- Room, 14 таблиц, 6 DAO, экспорт схемы версии 1.
- Инварианты заданы на уровне схемы, а не только в коде: уникальность
  `(conversation_id, client_msg_id)`, `(conversation_id, seq)`,
  `(client_op_id)`, каскадное удаление реакций.
- Сложные запросы проверены компилятором Room и тестами на настоящем
  SQLite через Robolectric.
- Список чатов собирается **одним запросом** с подзапросом непрочитанных,
  а не N+1 обращениями.

Проверенные инварианты (выборочно):

| Что проверено | Тест |
|---|---|
| Дубликат `clientMsgId` отвергается | `duplicate client message id is rejected by unique index` |
| Повторное подтверждение идемпотентно | `confirming the same operation twice is idempotent` |
| Неподтверждённые сообщения сортируются в хвост | `unconfirmed messages sort after confirmed ones` |
| Непрочитанные не считают свои и удалённые | `unread count ignores own and deleted messages` |
| Удаление сообщения стирает текст, но сохраняет строку | `deleting a message clears its body but keeps the row` |
| Курсор синхронизации не откатывается назад | `cursor never moves backwards` |
| Зависимая операция не уходит раньше зависимости | `dependent operation is not sent before its dependency` |
| Застрявшие операции восстанавливаются после перезапуска | `in flight operations are recovered to pending after restart` |

### 2.4. Offline-ядро (`:core:data`) — 13 тестов

**Запись полностью работает без сети.** Сетевого слоя ещё нет вовсе —
именно поэтому результат показателен.

Реализовано:

- Репозитории сообщений, чатов, задач, пользователей и состояния
  синхронизации.
- Оптимистичная запись и постановка операции в очередь — **одной
  транзакцией**.
- Очередь с расписанием повторов, зависимостями и схлопыванием операций
  (черновик не забивает очередь при быстром наборе).
- Создание задачи из сообщения со снапшотом текста.
- Смена статуса задачи с частичным PATCH, `baseVersion` и метками
  времени по полям.

Проверенные сценарии ТЗ §13:

| № | Сценарий | Тест |
|---|---|---|
| 1 | Отправка сообщения без интернета | `sending a message offline stores it locally and queues the operation` |
| 2 | Перезапуск приложения до синхронизации | `queue survives process restart and in flight work is recovered` |
| 3 | Повторная отправка одного события | `enqueueing the same client op id twice does not duplicate` |
| 10 | Восстановление после временной ошибки (частично) | `scheduling a retry increments attempt count and postpones` |

Плюс: удаление исходного сообщения не лишает задачу контекста
(`deleting the source message keeps the task readable`).

### 2.5. Design System (`:core:designsystem`) — 3 теста

- Оригинальная палитра: манго-оранжевый, морская волна, слива.
  Светлая и тёмная схемы, Dynamic Color (Android 12+).
- Семантические цвета вынесены отдельно от `ColorScheme`: Dynamic Color
  не подменяет их обоями — иначе «выполнено» могло бы стать красным.
- Типографика в `sp`, масштабируется системной настройкой размера шрифта.
- 18 компонентов: аватар с индикатором присутствия, пузырь сообщения
  с ответом и реакциями, элемент списка чатов, карточка задачи, чипы
  статусов и приоритетов, индикатор синхронизации, индикатор набора
  текста, пустые состояния, панели.
- Доступность: составные элементы объявляются одним узлом с осмысленным
  описанием — иначе TalkBack читает автора, текст, время и галочки
  доставки как четыре несвязанных элемента.

### 2.6. Безопасность (`:core:security`) — 7 тестов

- AES-256-GCM, ключ генерируется **внутри Android Keystore** и не покидает
  его. Случайный IV на каждую операцию.
- Неудачная расшифровка (сброс ключа Keystore) → сессия считается
  потерянной, данные стираются, вместо падения приложения.
- Тест `tokens are encrypted before being written` явно убеждается, что
  токены не видны в хранилище открытым текстом.
- Резервное копирование данных приложения отключено.

### 2.7. Настройки (`:core:datastore`) — 7 тестов

Приватные значения по умолчанию закреплены тестом: показ текста сообщения
в уведомлении **выключен**, медиа загружается только по Wi-Fi.

### 2.8. Приложение (`:app`) — 12 тестов

- Нижняя навигация из пяти разделов, сохранение состояния вкладок.
- Экран чатов и экран задач связаны с реальными ViewModel и репозиториями,
  читают данные из Room.
- Экран настроек — рабочий, изменения сохраняются и переживают перезапуск.
- Форматирование времени с корректными **русскими формами множественного
  числа** («1 день», «2 дня», «5 дней», «11 дней», «21 день»).
- Экраны переписки и карточки задачи — честные заглушки с указанием этапа,
  а не имитация работы на выдуманных данных.

### 2.9. Документация

синхронизации, план безопасности, OpenAPI (30 эндпоинтов, валидный
3.1.0), README.

## 6. Решения, повлиявшие на результат

### 6.1. Версии стека зафиксированы по доступному SDK

Текущая генерация androidx требует AGP 9.1 и compileSdk 37. Стек закреплён
на AGP 8.13.1 / compileSdk 36: это удовлетворяет актуальному требованию
Google Play и работает на установленном SDK.

*Обновление 12.11.2026:* `cmdline-tools` 23.0 установлены, технический
блокер снят. Решение остаться на `targetSdk 36` подтверждено владельцем
проекта; миграция на AGP 9.1 остаётся техническим долгом, см.
[ADR-0002](../adr/0002-build-toolchain.md).

Подбор версий выполнялся **пробными сборками**, а не по памяти. Выяснено
опытным путём: AGP 8.13.1 требует Gradle ≥ 8.13; Hilt 2.59+ требует AGP ≥ 9.0;
AGP 9.x убирает Kotlin-плагин и требует отдельной миграции.

### 6.2. Проект вынесен из OneDrive

Исходный каталог находился внутри OneDrive. Синхронизация регулярно
приводит к `Unable to delete directory build\...` и порче кэша Gradle.
Проект размещён в `C:\dev\mango-messenger`.

### 6.3. Пустые модули не создавались

`:core:network`, `:core:sync`, `:core:realtime` и `:feature:*` **не
созданы**. Каталог из пустых классов создаёт ложное впечатление
готовности; модули появятся вместе с содержимым.

### 6.4. Машинно-зависимые пути вынесены из репозитория

Путь к JDK не хранится в `gradle.properties`: он зависит от машины и в
коммитируемом файле ломал бы сборку у всех остальных. Вместо него —
`scripts/gradlew.sh` с автоопределением.

## 7. Ошибки, найденные автоматикой

Раздел приведён, потому что он показывает, что проверки реальны.

| Что нашло | Что было не так |
|---|---|
| Тест `status change patch depends on task creation while unsynced` | Конструктор операции очереди дублировался в двух репозиториях, и в одном зависимость не переводила операцию в `BLOCKED`. Исправлено выносом в одну функцию |
| Тест `timestampOf round trips` | `UuidV7` был объектом с глобальным состоянием — состояние протекало между тестами. Переделан в инжектируемый генератор |
| Тесты `SettingsStoreTest` | `SettingsStore` создавал DataStore внутри себя через делегат с кэшированием по имени — тесты видели состояние друг друга. DataStore сделан инжектируемым |
| Android Lint | `LocalDate.ofInstant` требует API 34 при `minSdk 26` — **падение на Android 8–13** |
| Android Lint | `BoxWithConstraints` без использования scope в аватаре — лишний subcomposition на каждый элемент списка чатов |
| Компилятор Kotlin | `java.util.random.RandomGenerator` — Java 17 API, отсутствует на Android 26 |

## 9. Чего этот отчёт не утверждает

- Что приложение готово к использованию. Обмена сообщениями в нём пока нет.
- Что целевые показатели производительности §11 ТЗ достигнуты.
  **Измерений не проводилось.**
- Что приложение работает на реальном устройстве. APK собран, но
  ни разу не установлен.
- Что безопасность проверена. Реализована часть мер по
  [плану](../architecture/security-plan.md); внешнего аудита не было.
