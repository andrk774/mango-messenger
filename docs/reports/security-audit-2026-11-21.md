# Проверка безопасности Mango — 21 ноября 2026

Проверена текущая рабочая копия `C:\dev\mango-messenger`, включая незакоммиченные
изменения. Это ограниченный аудит исходников, зависимостей и интеграционных сценариев,
не независимый пентест и не гарантия отсутствия других уязвимостей.
Рабочие аккаунты и данные не изменялись; исправления и развёртывание не выполнялись.

## Подтверждённые проблемы

### S1 — высокая: ADMIN может захватить аккаунт OWNER

`backend/app/src/main/kotlin/com/mango/backend/app/AdminService.kt:111–128`:
`resetPassword` проверяет право `manage` вызывающего, но не роль целевого аккаунта.
Обычный ADMIN может сменить пароль OWNER. Защита назначения ролей в `changeRole`
при этом обходится через вход под владельцем.

В изолированной тестовой БД созданы ADMIN и OWNER. Запрос сброса пароля владельца
от ADMIN вернул 200; вход с новым паролем прошёл; `/v1/admin/me` вернул OWNER.
Проверка ожидаемого запрета 403 завершилась ошибкой — воспроизведение подтверждено.
Предпосылка: атакующему уже нужны права ADMIN; обычный пользователь так действовать не может.

Исправление: явно определить и проверять матрицу прав для изменения чужих учётных
данных. Запретить ADMIN менять пароль OWNER и других привилегированных аккаунтов;
для собственного пароля использовать отдельный поток с повторной аутентификацией.
Проверять права и роль цели внутри транзакции с согласованной блокировкой с `changeRole`.

### S2 — средняя, зависит от способа публикации: обход лимита входа

`backend/auth/src/main/kotlin/com/mango/backend/auth/AuthRoutes.kt:133,247–259`:
ключ лимитера — пара email/IP. IP берётся из первого `X-Forwarded-For` без проверки
доверенного прокси. Комментарий о том, что заголовок используется только для журнала,
не соответствует фактическому использованию в rate limiter.

В тесте исчерпан лимит с одним заголовком: сервер возвращал 429. Изменение только
`X-Forwarded-For` дало 401 вместо 429 — пароль снова проверяется.
Это не успешный вход, а восстановление возможности перебора.

Текущий Compose привязывает backend к localhost, перед ним Caddy; тест НЕ доказывает
обход именно через этот прокси. Прямой доступ к backend или неверная настройка прокси
делают подмену применимой. Кроме того, распределённый перебор с настоящих разных IP
обходит единый лимит аккаунта, поскольку отдельного счётчика на email нет.

Исправление: доверять forwarded-заголовкам только от явно заданных прокси, закрыть
прямой доступ; независимо ограничивать попытки на аккаунт и источник. Проверить
маршрут через Caddy отдельным тестом. Не полагаться только на пару email/IP.

## Зависимости

Через OSV проверено 613 уникальных сочетаний ecosystem/package/version:
каталоги Maven, версии Kotlin Gradle Plugin, разрешённые runtime-графы backend и
Android release, полный Cargo.lock прототипа. Проверка ОС контейнеров, полного графа
build-tools и достижимости всех уязвимых методов в этот объём не входит.
