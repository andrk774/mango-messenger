# Админ-панель: подключения, вход и журнал — 27.11.2026

## Реализовано

- Kubernetes API только для чтения: серверный список разрешённых подключений,
  TLS с CA и проверкой hostname, короткоживущий токен ServiceAccount, обновление
  токена из файла, запрет redirect, ограничение ответа 2 МБ и двух одновременных
  проверок. В ответе только разрешённые поля состояний, без Secrets, env и логов.
- Локальный docker-desktop подключён через сеть kind и отдельный RBAC
  mango-panel-reader. Проверены реальные Deployment, Pod, PVC и Service.
  Чтение Secrets и изменение Deployment запрещены. Токен первоначально на 24 часа;
  постоянную ротацию внешних токенов ещё нужно настроить. См. docs/KUBERNETES_API.md.
- Веб-автовход: кнопка «Админ-панель» после проверки роли. MessageChannel между
  вкладками с проверкой origin и источника, ограниченными путями API и привязкой
  к сессии. Токены остаются в памяти вкладки мессенджера, не в URL/storage админки.
  Обновление админки повторяет handshake. Выход из Mango закрывает связанную панель.
  Прямое открытие /admin без вкладки Mango продолжает требовать вход.
- Генератор промокодов: 12 символов, криптографический генератор браузера,
  редактирование до сохранения; повторная генерация не создаёт запись на сервере.
- По явному выбору пользователя ADMIN и OWNER могут применять LiveKit/TURN.
  MODERATOR и USER доступа не имеют. Секреты остаются зашифрованными на сервере.
  Добавлена инструкция в форме. Реальный внешний LiveKit/TURN не настроен.
- Карточка пользователя: профиль, роль, баланс, Premium и действия с иконками.
  Вложенные формы возвращаются стрелкой назад; несохранённые формы удаляются из DOM.
- Назначение ролей остаётся только OWNER, действует защита последнего владельца.
  Для остальных ролей кнопка объясняет отсутствие разрешения.
- Журнал: «Пользователь», имя и username с переходом в профиль. Объект отображается
  иконкой с доступной подписью/tooltip; пользователь открывает профиль, остальные
  известные категории открывают соответствующий раздел. Профили — текущие данные.
- «Очистить журнал» для OWNER, ADMIN, MODERATOR и MANAGER с вводом подтверждения: перенос в архив, без
  удаления исходных записей; AUDIT_ARCHIVED фиксирует число записей. Архив доступен
  отдельно. На рабочей базе очистка не выполнялась.

## Проверки

- KubernetesApiTest: HTTPS, hostname, отказ TLS, ротация токена, запрещённые
  URL/namespace, redirects, ошибки доступа и отсутствие секретных полей в ответе.
- AdminFeaturesIntegrationTest: роли, API-права, профиль пользователя,
  архивирование с сохранением записи, сохранение настроек звонков ADMIN.
- scripts/test-web-ui.cjs --ops-only: автовход/перезагрузка/отзыв роли,
  отсутствие токенов в storage/URL, генератор кода, Kubernetes, формы назад,
  профили/иконки журнала, архив и права редактирования ролей.
- --admin-only: встроенный канал Android, настройки звонков, аналитика, поддержка.
- Визуальные снимки с тестовыми данными: artifacts/web-acceptance/.

Общий прогон всех модулей и реальный внешний кластер в эту приёмку не входят.
Изменения веб-панели загружаются с backend, новый Android APK для них не нужен.
