# Kubernetes API в панели Mango

Панель запрашивает реальное состояние через backend. Доступ: OWNER и ADMIN.
MODERATOR и обычные пользователи получают 403. Учётные данные кластера не
передаются браузеру. Подключение не переключает пользователей на этот кластер.

## Возможности

- Проверка HTTPS API и токена ServiceAccount.
- Готовность заданного Deployment, поколения конфигурации и число реплик.
- Pod: состояние, готовность контейнеров и число перезапусков.
- PVC: состояние; заданный Service: тип.
- Время проверки, отдельные ошибки токена, RBAC, отсутствующего ресурса и сети.
- До 200 Pod/PVC за проверку; при усечении показывается предупреждение.

Это интеграция только для чтения. Перезапуск, обновление, откат и журналы остаются
командами оператора. Состояние проверяется по кнопке, непрерывного мониторинга нет.
API недоступен — это ошибка проверки, а не доказательство остановки приложения.

## Подключение

1. Подготовьте namespace и ограниченный ServiceAccount. Пример:
   `infrastructure/kubernetes/admin-api-rbac.yaml`. Перед применением замените
   namespace и имена ресурсов под целевой кластер. Нет доступа к Secrets,
   exec, logs и изменению ресурсов.
2. Смонтируйте CA кластера и токен в backend только для чтения.
3. Создайте закрытый JSON-файл по образцу
   `infrastructure/kubernetes/api-connections.example.json`.
4. Укажите `MANGO_KUBERNETES_CONFIG_FILE`, либо используйте путь по умолчанию
   `/run/secrets/mango/kubernetes/connections.json`.
5. Обновите раздел «Настройки сервера» и нажмите «Проверить состояние».

В Compose каталог secrets уже смонтирован. Для текущего локального kind-кластера
используется дополнительный файл `infrastructure/docker/compose.kubernetes-api.local.yml`,
подключающий backend к существующей сети kind. Адрес API — имя control-plane
контейнера и порт 6443, совпадающее с SAN сертификата. Не используйте этот override
для внешнего кластера. При последующем пересоздании локального backend снова
передавайте оба Compose-файла.

Внешний кластер добавляется отдельной записью в серверный JSON. Разрешены только
HTTPS origin без пути, userinfo и query; namespace/Deployment/Service заданы
оператором. Профили из формы панели не могут изменять этот список или адреса API.
Файлы перечитываются при проверке: ротация токена не требует перезапуска Mango.

Для локальной проверки 27.11.2026 выдан ограниченный токен на 24 часа. Это не
бессрочное подключение: после истечения нужно выпустить новый TokenRequest и
обновить файл токена. Для постоянной эксплуатации внутри Kubernetes используйте
projected ServiceAccount token с автоматической ротацией; для внешнего подключения
нужен отдельный процесс обновления короткоживущих токенов.

Не добавляйте credentials в Git, поля панели, команды с буквальным токеном или
скриншоты. Не отключайте проверку TLS и не используйте cluster-admin для панели.

Основа: [Service Accounts](https://kubernetes.io/docs/concepts/security/service-accounts/),
[RBAC](https://kubernetes.io/docs/reference/access-authn-authz/rbac/).
