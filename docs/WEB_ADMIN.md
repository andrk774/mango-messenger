# Главная страница, Mango Web и администрирование

Назначение владельца при установке и права ролей: [Роли сервиса](SERVICE_ROLES.md).

Все страницы обслуживаются существующим Kotlin backend и работают с той же базой,
что Android. Отдельный Node.js-сервер в эксплуатации не нужен.

| Адрес | Назначение |
| --- | --- |
| `/` | Главная страница с переходом в Mango Web |
| `/web/` | Пользовательские чаты и задачи |
| `/admin/` | Панель администратора сервиса |

Для локального стенда адрес — `https://mango.home.arpa/`. На другом устройстве
нужны доступ к сети сервера, разрешение этого имени в IP ноутбука и доверие
локальному корневому сертификату Caddy. Адрес не опубликован в интернете.
`http://localhost:8081/` подходит для проверки непосредственно на ноутбуке.
Для работы через сеть используйте HTTPS: загрузка файлов и идентификаторы
операций используют браузерные API защищённого контекста.

На момент проверки 19 ноября имя `mango.home.arpa` на ноутбуке автоматически
не разрешалось. Рабочая ссылка непосредственно на ноутбуке —
`http://localhost:8081/`; для сетевого имени настройте локальный DNS/hosts.

## Возможности пользователя

- Вход существующим аккаунтом, регистрация, подтверждение email и восстановление пароля.
- Поиск собеседников, создание личного или группового чата.
- Чтение сообщений, отправка текста и файлов, ссылки, копирование, эмоджи и реакции.
- Создание личных и общих задач, назначение участников чата, сроки, статусы и комментарии.
- Превращение сообщения в задачу, просмотр собственных баллов и срока подписки.
- Жалоба на участника через список участников чата.

Список чатов и открытая история обновляются каждые 5 секунд, пока вкладка видима.
Открытая история загружает последние 100 сообщений; более ранние доступны кнопкой.
Задачи загружаются до 500 за выборку; это первая версия без пагинации задач.
При временной ошибке отправки повтор использует тот же идентификатор сообщения.
Черновики и неотправленный файл существуют только до закрытия или обновления страницы:
постоянная офлайн-очередь Android здесь не воспроизведена.

Автовход: access-токен находится в памяти страницы, refresh-токен — в HttpOnly-cookie
с SameSite=Strict и ограниченным путём `/v1/auth`. На реальных доменах cookie требует
HTTPS; HTTP допускается только на localhost/127.0.0.1. Пароль и токены не сохраняются
в localStorage. После обновления страницы сессия восстанавливается, пока она действительна.
Прямой вход в `/admin/` использует ту же браузерную сессию и повторно проверяет роль.
Выход отзывает сессию и очищает cookie; при недоступном сервере предлагается повторить выход.
Вкладки сериализуют обновление cookie через Web Locks (проверено в Chrome).
Голосовой файл можно отправить вложением и скачать;
запись голоса в браузере, полноценный медиаплеер, звонки, браузерные push и QR-вход
в эту версию не входят. Встроенные Android-стикеры пока не перенесены в браузер.

## Права администратора

Владение группой или совпадение email с настройкой не выдаёт прав сервиса.
Право хранится явно в `service_admins`; каждый административный API проверяет его.
Публичная HTML-форма входа не содержит данных пользователей.

Первый администратор назначается оператором через БД **только после проверки
существующего подтверждённого аккаунта**. Пример для локального Compose:

```sql
BEGIN;
WITH granted AS (
  INSERT INTO service_admins(user_id)
  SELECT id FROM users
  WHERE email = 'ACCOUNT_EMAIL' AND email_verified AND deleted_at IS NULL
    AND NOT EXISTS (SELECT 1 FROM user_blocks WHERE user_id = users.id)
  ON CONFLICT DO NOTHING
  RETURNING user_id
)
INSERT INTO admin_audit(actor_id, action, target, detail)
SELECT user_id, 'BOOTSTRAP_ADMIN', user_id::text, 'Granted by server operator'
FROM granted;
COMMIT;
```

Панель позволяет:

- искать пользователей по email/username, изменять отображаемое имя и username;
- устанавливать новый пароль (12–128 символов) с завершением прежних сессий;
- блокировать и разблокировать пользователей с указанием причины;
- рассматривать жалобы и записывать решение;
- начислять/списывать внутренние баллы, добавлять/вычитать дни и календарные месяцы подписки;
- видеть историю корректировок и журнал административных действий;
- менять название сервера и разрешение регистрации;
- создавать, проверять и выбирать SMTP-профили;
- видеть счётчики, доступность БД, время работы, свободное место и наличие настроек Redis/Firebase.

Блокировка запрещает вход, refresh и доступ по ранее выданным JWT, закрывает
WebSocket (проверка перед событиями и каждые 5 секунд) и отзывает push-токены устройств.
Разблокировка не восстанавливает старые сессии. Для администраторов блокировка через
панель запрещена. После смены собственного пароля администратор входит снова.

Корректировка баланса атомарна и имеет UUID `requestId`: повтор того же запроса
не начисляет баллы дважды. Повтор идентификатора с другими данными отклоняется.
Баланс не может стать отрицательным. Продление положительными значениями начинается
с более поздней из дат «сейчас» и конца текущей подписки; месяцы календарные, UTC.
Подписка пока является учётной записью срока: платёжная система и ограничения
функций по подписке не включены.

## SMTP и секреты

По умолчанию продолжает работать SMTP из переменных окружения (локально Mailpit).
Создание профиля не активирует его автоматически. Сначала сохраните профиль,
нажмите «Проверить», затем «Выбрать». Проверка соединяется и авторизуется,
но **не отправляет письмо**. Реальная отправка происходит при регистрации/восстановлении.

Шаблоны: Mailpit `mailpit:1025` без TLS, Gmail `smtp.gmail.com:587` STARTTLS,
Яндекс `smtp.yandex.ru:465` TLS, произвольный SMTP. Данные авторизации внешнего
провайдера вводятся оператором. Без TLS разрешён только локальный/тестовый режим,
а SMTP с логином и паролем всегда требует TLS или STARTTLS.

Пароль профиля шифруется AES-GCM и не возвращается в API, HTML или аудит.
Пустое поле пароля при редактировании сохраняет прежний пароль только при прежнем
логине. Изменение логина требует нового пароля; очистка логина убирает авторизацию.

Ключ шифрования берётся из `MANGO_ADMIN_ENCRYPTION_KEY`, если он непустой,
иначе выводится из существующего `MANGO_JWT_SECRET` с отдельным контекстом.
Для отдельного ключа задайте случайный секрет не менее 32 байт до создания профилей.
Compose передаёт эту переменную, Kubernetes принимает её через Secret `mango-runtime`.
Смена применяемого ключа без переноса зашифрованных значений делает сохранённые
пароли SMTP нечитаемыми — профили потребуется заполнить заново.
Резервируйте БД и соответствующий ключ отдельно от исходников; не публикуйте `.env`.

Настройка SMTP в панели не изменяет Firebase, ключ подписи Android, БД или Redis.
Статус «настроен» не является проверкой доставки push или работоспособности Redis.

## Дополнительные REST-маршруты

Для защищённых маршрутов используется `Authorization: Bearer …`.
Ответы не кешируются. Полный действующий набор полей — в `AdminRoutes.kt`,
`AdminService.kt`, `WebRoutes.kt`; существующие чаты/задачи используют `openapi.yaml`.

| Метод и маршрут | Доступ / данные |
| --- | --- |
| `GET /v1/site` | Публично: `name`, `registrationOpen` |
| `GET /v1/users/me/account` | Свои `points`, `subscriptionUntil` |
| `POST /v1/reports` | Пользователь: `targetId`, `reason`; до 10 обращений/час |
| `GET /v1/admin/me` | Проверка права сервиса |
| `GET /v1/admin/overview` | Счётчики и состояние backend |
| `GET /v1/admin/users?q=&offset=0` | Пользователи, до 50 записей |
| `POST /v1/admin/users/{id}/identity` | `name`, `username`, `reason` |
| `POST /v1/admin/users/{id}/password` | `password`, `reason` |
| `POST /v1/admin/users/{id}/block` | `blocked`, `reason` |
| `POST /v1/admin/users/{id}/balance` | `requestId`, `points`, `days`, `months`, `reason` |
| `GET /v1/admin/users/{id}/ledger` | Последние 100 корректировок |
| `GET /v1/admin/reports?offset=0` | Жалобы, до 50 записей |
| `POST /v1/admin/reports/{id}` | `status`: OPEN/REVIEWING/RESOLVED/REJECTED; `resolution` |
| `GET /v1/admin/audit?offset=0` | Журнал, до 50 записей |
| `GET /v1/admin/settings` | Название, регистрация, выбранный SMTP |
| `POST /v1/admin/settings` | `serverName`, `registrationOpen` |
| `GET /v1/admin/smtp-profiles` | Профили без паролей; признак `hasPassword` |
| `POST /v1/admin/smtp-profiles` | `id`, `name`, `host`, `port`, `security`, `sender`, `username`, `password` |
| `POST /v1/admin/smtp-profiles/{id}/test` | Проверка соединения без отправки письма |
| `POST /v1/admin/smtp-select` | `id` профиля либо `null` для SMTP окружения |

## Проверки

```powershell
# В backend/, с доступным Docker для Testcontainers:
.\gradlew.bat test --console=plain

# Из корня, с установленным Playwright и Chrome:
node scripts/test-web-ui.cjs C:\path\to\node_modules\playwright
```

`AdminIntegrationTest` проверяет реальные SQL-транзакции и HTTP/WS-авторизацию
в отдельной тестовой базе. `test-web-ui.cjs` использует явно синтетические
данные API и проверяет браузерные сценарии, CSP, экранирование текста, мобильную
компоновку и повторную отправку. Его скриншоты не подтверждают состояние живой БД.
# Kubernetes: режим оператора

В разделе «Настройки» находится блок «Kubernetes · настройки и обслуживание».
Администратор и владелец могут сохранить контекст kubectl, namespace, имя Deployment
и Service backend. Параметры хранятся на сервере; изменения записываются в журнал.
Модератор доступа к этим настройкам не имеет.

Панель готовит команды проверки доступа, состояния Pod/PVC/Service, событий,
последних логов, ожидания готовности, port-forward и перезапуска backend.
Копирование команды не выполняет её: оператор проверяет команду и запускает её
в своём терминале. Несохранённые изменения формы не меняют команды.

Это не подключение к Kubernetes API и не мониторинг кластера. Kubeconfig,
токены и сертификаты в форму не вводятся. Имена ограничены безопасными короткими
идентификаторами; для сложного имени контекста используйте локальный псевдоним.
Перезапуск может прервать работу, а port-forward доступен только на localhost.
Удаление кластеров, namespace и томов через панель не предусмотрено.

Проверено 20 ноября 2026: интеграционные тесты AdminIntegrationTest (авторизация,
сохранение, журнал и отклонение командных конструкций), браузерные сценарии
с тестовыми ответами API, включая мобильную ширину и повторное открытие настроек.
# Внешние профили Kubernetes

В разделе **Настройки сервера → Kubernetes → Внешние кластеры** доступны добавление,
редактирование и удаление до пяти профилей. Сохраняются имя, локальный псевдоним
kubectl-контекста, namespace, deployment, service и необязательный публичный домен.
Доступ разрешён OWNER/ADMIN, модератору запрещён. Данные валидируются сервером,
токены/kubeconfig/сертификаты не принимаются. Удаление профиля не удаляет кластер.

Панель генерирует команды для оператора и явно показывает «подключение не проверено».
Она не устанавливает соединение с внешним кластером, не создаёт DNS/HTTPS и не
выполняет команды. Сначала настройте kubectl на компьютере оператора. Не добавляйте
личные ключи или пароли в названия полей. Публичный домен является справочным полем.
