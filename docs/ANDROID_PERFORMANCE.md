# История чата и измерения Android

## Исправление истории (28 ноября 2026)

Экран начинал с последних 200 сообщений и никогда не расширял подписку Room,
хотя серверная догрузка сохраняла более старые записи. Теперь окно увеличивается
на 100 записей при достижении начала видимой истории. Кэш доступен и без сети.
Повторный запрос во время загрузки блокируется; пустая серверная страница означает
конец истории. UI ждёт завершения текущей загрузки перед следующей страницей.
Стабильные ключи сообщений в LazyColumn сохранены.

Запросы реакций разделены на группы по 500 ID для совместимости с лимитом
параметров SQLite на старых Android.

Регрессионные тесты:
- `ConversationHistoryTest`: 450 сообщений, расширение окна, ошибка сети,
  отсутствие дублей, блокировка параллельной загрузки и конец истории.
- `MessageDaoTest`: настоящая SQLite через Robolectric, выборка 450 записей.

Итоговый прогон 28 ноября: `:app:testDebugUnitTest` — 44,
`:core:database:testDebugUnitTest` — 32, `:core:data:testDebugUnitTest` — 19;
всего 95 тестов, без ошибок. Лог: `artifacts/history-tests-final-20261128.log`.
Позднее исправленный APK установлен на Galaxy и проверен на отдельном чате из
450 сообщений онлайн и без сети после перезапуска. Протокол, хеш APK и замеры:
[приёмка Galaxy](reports/history-galaxy-2026-11-28.md).

Это постепенное расширение списка, а не полноценный Paging 3 с вытеснением страниц:
память растёт с просмотренной историей. Для десятков тысяч сообщений необходимы
отдельный нагрузочный сценарий и переход UI на PagingData.

## Воспроизводимые замеры

Скрипт `scripts/measure-android-performance.py` использует ADB и стандартную
библиотеку Python. Он не очищает данные приложения и не собирает текст сообщений.
`startup` принудительно останавливает только указанный пакет перед каждым запуском;
не запускайте его во время записи голосового или другого несохранённого действия.

```powershell
python scripts/measure-android-performance.py --serial DEVICE_SERIAL --mode startup --iterations 10 --output artifacts/performance/startup.json
# Откройте тестовый чат, дождитесь загрузки, закройте клавиатуру и шторку уведомлений.
python scripts/measure-android-performance.py --serial DEVICE_SERIAL --mode scroll --iterations 20 --output artifacts/performance/scroll.json
```

Для сравнения используйте один APK/серверный стенд и одинаковую переписку
(например, 500/5000/10000 сообщений), ориентацию, частоту экрана и состояние сети.
Записывайте hash APK, число сообщений и состояние кэша рядом с JSON.
Не сравнивайте debug с release. Исключите перегрев и параллельные действия.

Результаты: отдельные `am start -W TotalTime`, медиана и p95 запуска Activity;
`gfxinfo` — количество кадров, janky frames и перцентили; `meminfo` — PSS/RSS.
TotalTime не является временем готовности переписки. Это диагностические ADB-замеры,
не Macrobenchmark/TTFD и не измерение батареи. Для release performance gate нужны
выделенный benchmark-модуль, контролируемые фикстуры и Perfetto-трассы.

Первый замер прокрутки 28 ноября: Galaxy SM-S948B, Android 17, установленный до
исправления release, короткий тестовый чат, 10 жестов: 821 кадр, 10 janky (1,22%),
p95 6 мс; PSS 103886 КБ. Артефакт `artifacts/performance/scroll-before-20261128.json`.
Это проверка работоспособности измерителя, не оценка большой истории и не
доказательство ускорения после исправления.
