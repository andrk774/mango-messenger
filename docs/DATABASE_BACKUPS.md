# Бэкап и восстановление базы

Админ-панель → Настройки → Резервные копии базы. Только роль OWNER:
полная копия содержит данные всех пользователей и служебные настройки.

«Создать бэкап» запускает `pg_dump --format=custom` на сервере. После успешного
дампа проверяется его каталог, вычисляется SHA-256 и сохраняется JSON-манифест.
Операция выполняется в фоне, панель опрашивает статус. Команды запускаются
фиксированными аргументами без shell. Пароль БД передаётся через окружение
процесса; вывод утилит не возвращается браузеру.

Копии находятся в `/data/backups`, Docker volume `mango_backups`.
У backend должны быть `pg_dump`, `pg_restore`, `createdb` версии 17 или
совместимой с сервером. Dockerfile устанавливает клиент PostgreSQL 17.
Другие развёртывания: `MANGO_BACKUP_DIR` и `MANGO_PG_BIN`; каталог копий
должен быть постоянным томом, доступным только сервисному пользователю.

## Восстановление

Выберите копию и нажмите «Восстановить в отдельную базу», затем введите её ID.
Сервис проверит SHA-256, создаст уникальную `mango_restore_<uuid>`, восстановит
дамп в одной транзакции и проверит таблицу миграций. Результат содержит имя
восстановленной базы. Нужны права `CREATEDB` у серверного пользователя PostgreSQL.
Никакие существующие базы автоматически не удаляются и не заменяются.
Неудачная отдельная база сохраняется для диагностики.

Переключение рабочего сервиса на восстановленную базу — отдельная операция
оператора с остановкой записей и свежей копией текущей базы. Панель намеренно
не переключает соединения и не завершает пользовательские сессии. Перед
переключением необходимо согласовать восстановление вложений и ключей, проверить
совместимость версии приложения и отозвать восстановленные старые сессии.

## Что входит в копию

В панели копируется только PostgreSQL: пользователи, сообщения, задачи,
служебные настройки и зашифрованные секреты настроек. Файлы вложений и ключи
из `/run/secrets/mango` не входят в дамп. Для читаемости зашифрованных настроек
нужны исходные ключи. Копия на том же ноутбуке не защищает от потери диска.
Автоматического расписания, удаления старых архивов и импорта произвольных
загруженных SQL-архивов пока нет. Незавершённые дампы без манифеста не отображаются.

Для копии БД и вложений на ноутбук используйте `scripts/backup-local.ps1`;
для согласованной пары приостановите записи приложения. Проверка такой копии:
`scripts/verify-backup.ps1 -BackupDirectory <каталог>` — отдельная база,
без удаления рабочей. Ключи резервируйте отдельно в защищённом месте.
