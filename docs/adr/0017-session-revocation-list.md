# ADR-0017: Список отозванных сессий закрывает окно действия JWT

- **Статус:** принято
- **Дата:** 2026-11-12
- **Этап:** 4

## Контекст

Access token — подписанный JWT. Он проверяется без обращения к базе,
и это его главное достоинство: проверка стоит одну операцию над подписью
и масштабируется без общего состояния.

Обратная сторона обнаружилась при сквозной проверке живого стека:
**закрытие сессии не прекращает действие уже выданного токена**.
Проверка показала, что после обнаружения кражи refresh token и отзыва
всех сессий старый access token продолжал открывать доступ к переписке.

Это обесценивает именно ту защиту, ради которой сделано обнаружение
повторного использования ([ADR-0013](0013-refresh-rotation-and-reuse-detection.md)):
злоумышленник сохранял доступ ещё до пятнадцати минут — ровно тогда,
когда дорога каждая минута.

То же касается выхода из приложения и смены пароля после кражи.

## Решение

Введён список отозванных сессий. При закрытии сессии её идентификатор
помещается в список на время жизни access token; проверка токена
отвергает токены отозванных сессий.

Список пополняется при: выходе, отзыве сессии владельцем, смене пароля
и обнаружении повторного использования refresh token.

Запись живёт ровно столько, сколько мог бы прожить выданный под эту
сессию токен: дальше она бесполезна, потому что токен истечёт сам.

Реализации две:

| Где | Реализация | Корректность |
|---|---|---|
| Один экземпляр | в памяти процесса | полная |
| Несколько экземпляров | Redis | полная |
| Redis недоступен | проверка пропускает запрос | окно возвращается к сроку жизни токена |

**Внесение в список выполняется после фиксации транзакции.** Иначе откат
оставил бы в списке сессии, которые на самом деле продолжают действовать,
и пользователь оказался бы заблокирован без причины.

## Альтернативы

- **Проверять сессию в базе на каждый запрос.** Отклонено: обесценивает
  выбор JWT, добавляя обращение к базе в каждый запрос.
- **Сократить срок жизни access token до секунд.** Отклонено: обновление
  токена стало бы постоянным, а на плохой связи — источником отказов.
- **Оставить как есть и описать как известное ограничение.** Отклонено:
  обнаружение кражи токена — заявленная защита, и задержка в четверть
  часа лишает её смысла.
- **Жёсткий отказ при недоступности Redis.** Отклонено: сбой хранилища
  превратился бы в отказ в обслуживании для всех пользователей.

## Последствия

- Проверка токена перестала быть полностью автономной: в установке
  из нескольких экземпляров она обращается к Redis. Это одна операция
  чтения по ключу.
- Недоступность Redis временно возвращает прежнее поведение. Это
  зафиксированное ослабление, а не незамеченное.
- Поведение закреплено тестами: после выхода, после смены пароля и после
  обнаружения кражи ранее выданный токен получает отказ 401.
