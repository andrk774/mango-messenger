# ADR-0003: Room — единственный источник истины для интерфейса

- **Статус:** принято
- **Дата:** 2026-11-12
- **Этап:** 1

## Контекст

Требование offline-first означает, что приложение остаётся полезным без сети.
Распространённый антипаттерн — экран подписан на сеть, а база используется как
«кэш на случай ошибки». В таком варианте офлайн всегда выглядит как сбой,
а состояния «данные из кэша» и «данные с сервера» расходятся.

## Решение

Поток данных строго однонаправленный:

```
сеть / WebSocket  ──►  Room  ──►  Repository  ──►  ViewModel  ──►  Compose
                        ▲
                        └── локальные изменения (оптимистичная запись)
```

Экран **никогда** не подписывается на сеть. Любое сетевое событие сначала
записывается в Room, и уже изменение в Room обновляет интерфейс. Все методы
чтения в репозиториях возвращают `Flow` из Room.

Любая запись применяется к Room немедленно и ставится в очередь исходящих
операций. Метод репозитория возвращает успех, если изменение **сохранено
локально**; доставка на сервер — отдельный асинхронный процесс.

## Альтернативы

- **Сеть как источник истины, база как кэш.** Отклонено: не выполняет
  требование offline-first.
- **Два источника с объединением в ViewModel.** Отклонено: расхождение
  состояний и дублирование логики слияния на каждом экране.

## Последствия

- Экран мгновенно показывает данные при запуске — без «спиннера на всё окно».
- Отправка сообщения в офлайне неотличима от отправки в онлайне с точки зрения
  кода экрана; различается только индикатор состояния.
- Обязателен индикатор синхронизации: пользователь должен понимать, что
  изменение ещё не доставлено, иначе «сохранено локально» выглядит как
  «отправлено».
- Любое новое поле, нужное интерфейсу, обязано появиться в схеме Room,
  а значит потребует миграции.
