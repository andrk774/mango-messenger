# ADR-0012: Пароли — Argon2id на Bouncy Castle, параметры хранятся в самом хеше

- **Статус:** принято
- **Дата:** 2026-11-12
- **Этап:** 3

## Контекст

Хеш пароля должен быть дорог для перебора. Основная угроза — не подбор
по сети (его закрывает ограничение частоты), а офлайн-перебор по
украденному дампу базы на специализированном оборудовании.

bcrypt и PBKDF2 нагружают процессор, но почти не требуют памяти, поэтому
перебор хорошо распараллеливается на GPU и ASIC. Argon2id дополнительно
требует настраиваемый объём памяти, который плохо масштабируется на таком
оборудовании.

Реализации Argon2 для JVM:

- `de.mkammerer:argon2-jvm` — обёртка над нативной библиотекой через JNI;
- Bouncy Castle (`bcprov-jdk18on`) — чистая Java.

## Решение

Argon2id через Bouncy Castle. Параметры по умолчанию: память 64 МиБ,
3 итерации, параллелизм 1 — настраиваются переменными окружения.

Хеш хранится в формате PHC:

```
$argon2id$v=19$m=65536,t=3,p=1$<salt>$<hash>
```

Параметры стоимости лежат **внутри строки** и при проверке берутся
оттуда, а не из текущей конфигурации.

Проверка пароля сравнивает байты через `MessageDigest.isEqual`
(постоянное время). Повреждённая строка хеша трактуется как
несовпадение, а не как исключение.

## Альтернативы

- **argon2-jvm (JNI).** Отклонено: тянет нативную библиотеку, которая
  не загружается в slim- и alpine-образах без дополнительных зависимостей.
  Сбой проявится при развёртывании, а не при сборке.
- **bcrypt.** Отклонено: не требует памяти, перебор дешевле на порядки.
- **Хранение параметров в конфигурации.** Отклонено: повышение стоимости
  разом сделало бы недействительными все существующие пароли.

## Последствия

- Рост параметров безопасен: старые хеши продолжают проверяться, а при
  успешном входе пароль перехешируется с новой стоимостью (`needsRehash`) —
  это единственный момент, когда пароль доступен в открытом виде.
- Память 64 МиБ на проверку ограничивает число одновременных входов.
  При нагрузке это узкое место, и его придётся учитывать при
  масштабировании, а не «оптимизировать» снижением стоимости.
- В тестах стоимость снижена до 1 МиБ и 1 итерации: они проверяют логику,
  а не подбор параметров.
- Исключение при повреждённом хеше превратилось бы в ответ 500, по которому
  можно отличить существующую учётную запись от отсутствующей, —
  поэтому такой случай возвращает «не совпало». Закреплено тестом.
