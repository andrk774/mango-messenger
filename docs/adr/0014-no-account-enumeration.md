# ADR-0014: Регистрация и восстановление не раскрывают, зарегистрирован ли адрес

- **Статус:** принято
- **Дата:** 2026-11-12
- **Этап:** 3

## Контекст

Эндпоинт, который отвечает «этот адрес уже занят», позволяет проверить
по списку адресов, кто пользуется сервисом. Для мессенджера это само по себе
чувствительная информация: факт наличия учётной записи связывает человека
с сервисом и с его контактами.

Тот же вопрос возникает в трёх местах: регистрация, восстановление пароля
и вход.

## Решение

| Операция | Поведение |
|---|---|
| Регистрация, адрес свободен | `202 Accepted`, письмо со ссылкой подтверждения |
| Регистрация, адрес занят | `202 Accepted`, **тот же ответ**, письмо владельцу: «на этот адрес уже есть учётная запись» |
| Восстановление пароля, адрес известен | `202 Accepted`, письмо со ссылкой |
| Восстановление пароля, адрес неизвестен | `202 Accepted`, письмо не отправляется |
| Вход, неверный пароль | `401`, текст «Неверный адрес или пароль» |
| Вход, адреса нет | `401`, **тот же текст**, и так же выполняется проверка пароля против эталонного хеша |
| Регистрация, занято имя пользователя | `409 Conflict`, прямо |

Три пояснения к таблице.

**Почему при входе выполняется заведомо бесполезная проверка пароля.**
Argon2id с параметрами по умолчанию занимает десятки миллисекунд. Если для
несуществующего адреса пропустить проверку, ответ придёт заметно быстрее,
и время ответа выдаст наличие учётной записи не хуже текста ошибки.

**Почему проверка подтверждения адреса стоит после проверки пароля.**
Ответ «адрес не подтверждён» сообщает, что учётная запись существует.
Он допустим только тому, кто уже доказал знание пароля.

**Почему имя пользователя — исключение.** `username` публичен: он участвует
в поиске людей и отображается в профиле. Скрывать его занятость
бессмысленно, а прямой ответ избавляет от непонятной ошибки при регистрации.

## Альтернативы

- **Отвечать `409` на занятый адрес.** Отклонено: это и есть перечисление
  учётных записей. Выравнивание времени ответа тут не помогает — код
  состояния раскрывает всё сам.
- **Молчать и не писать владельцу.** Отклонено: человек не узнает,
  что кто-то пытается зарегистрироваться на его адрес.

## Последствия

- Пользователь, забывший о существующей учётной записи, получит
  `202` и письмо-предупреждение вместо понятного «вы уже зарегистрированы».
  Текст письма обязан объяснять ситуацию и вести к восстановлению пароля.
- Ответ `202 Accepted` вместо `201 Created` — осознанный выбор: сервер
  не может утверждать «создано», не раскрывая исход.
- Контракт OpenAPI приведён в соответствие: прежний черновик описывал
  `409` для занятого адреса, что противоречило бы этому решению.
- Поведение закреплено тестами
  `повторная регистрация на занятый адрес не раскрывает его занятость` и
  `неверный пароль и неизвестный адрес дают одинаковый ответ`.
