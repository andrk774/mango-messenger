# ADR-0002: Версии сборочного стека зафиксированы по доступному SDK

- **Статус:** принято, частично пересмотрено 2026-11-12 (см. «Обновление»)
- **Дата:** 2026-11-12
- **Этап:** 2

## Обновление от 2026-11-12

`cmdline-tools` версии 23.0 **установлены** в SDK по запросу владельца
проекта. Технический блокер, описанный ниже, снят: пакеты SDK теперь можно
доустанавливать из командной строки.

Что это меняет:

- доустановка платформ и build-tools возможна (`android sdk install ...`);
- создание AVD возможно (`avdmanager`), а значит становятся доступны
  UI-тесты и профилирование — после загрузки системного образа;
- основная лицензия Android SDK была принята ранее через Android Studio,
  новых согласий не потребовалось. В cmdline-tools 23.0 команда
  `sdkmanager --licenses` объявлена ненужной, а сам `sdkmanager` заменён
  новым `android` CLI.

Что **не** меняется: связка версий остаётся прежней. `targetSdk 36`
подтверждён владельцем проекта, миграция на AGP 9.1 + compileSdk 37
остаётся отдельной задачей и выполняется только по явному решению —
она требует переписывания сборочных скриптов (AGP 9 убирает плагин
`org.jetbrains.kotlin.android`).

## Контекст

На машине разработки установлен Android SDK с платформами до **android-36**
включительно и build-tools **34.0.0** и **36.0.0**. На момент принятия решения
`cmdline-tools` (а с ними `sdkmanager`) отсутствовали, поэтому доустановить
недостающие пакеты SDK из командной строки было нельзя. *Позже это
ограничение снято — см. «Обновление» выше.*

Проверка актуальных версий библиотек показала, что текущая генерация androidx
(compose 1.12, core-ktx 1.19, lifecycle 2.11, navigation 2.10, hilt 2.59+)
требует **AGP 9.1 и compileSdk 37**. Платформы android-37 в системе нет;
на момент принятия решения не было и возможности её установить.

Дополнительно проверено сборкой:

- AGP 8.13.1 требует Gradle ≥ 8.13; кэшированный Gradle 8.11.1 не подходит.
- Hilt 2.59 и новее требуют AGP ≥ 9.0.
- AGP 9.x убирает плагин `org.jetbrains.kotlin.android` (Kotlin встроен),
  то есть требует отдельной миграции.

## Решение

Фиксируется связка, **проверенная реальной сборкой** в этом окружении:

| Компонент | Версия |
|---|---|
| Gradle | 9.3.1 |
| AGP | 8.13.1 |
| Kotlin | 2.2.21 |
| KSP | 2.2.21-2.0.5 |
| Hilt | 2.58 (последняя совместимая с AGP 8) |
| Room | 2.8.5 + Room Gradle Plugin |
| Compose BOM | 2026.03.01 |
| compileSdk / targetSdk | 36 |
| buildToolsVersion | 36.0.0 |
| minSdk | 26 |
| JVM target | 17 |

`minSdk 26` выбран потому, что `java.time` доступен нативно начиная с API 26,
без core library desugaring.

## Альтернативы

- **AGP 9.1 + compileSdk 37 + последние библиотеки.** Отклонено на этом этапе.
  Изначально было технически невозможно (нет `cmdline-tools`); после их
  установки остаётся отложенным по двум причинам: `targetSdk 36` подтверждён
  владельцем проекта, и AGP 9 требует отдельной миграции сборочных скриптов
  (убран плагин `org.jetbrains.kotlin.android`).
- **Откат на compileSdk 34** (под установленный build-tools 34.0.0). Отклонено:
  `targetSdk 34` не удовлетворяет текущим требованиям Google Play.

## Последствия

- Сборка полностью работает на установленном SDK, без сетевых загрузок SDK.
- `targetSdk 36` соответствует актуальному требованию Google Play.
- Библиотеки на одну генерацию старше последних. Это **технический долг**:
  задача миграции на AGP 9.1 + compileSdk 37 зафиксирована в плане развития.
- Версии живут в `android/gradle/libs.versions.toml`; обновлять их следует
  только вместе с проверкой сборки, а не «по одной строке».
