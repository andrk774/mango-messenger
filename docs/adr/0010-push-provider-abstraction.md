# ADR-0010: Push через абстракцию провайдера, FCM — одна из реализаций

- **Статус:** принято
- **Дата:** 2026-11-12
- **Этап:** 1

## Контекст

ТЗ требует возможность заменить push-провайдера. Кроме того, FCM требует
проекта Firebase и файла `google-services.json`, которых у проекта пока нет,
а блокировать разработку из-за этого нельзя.

Отдельно: содержимое переписки в push-payload проходит через инфраструктуру
провайдера. Это утечка, не зависящая от TLS.

## Решение

- Доставка push описывается интерфейсом `PushProvider` на сервере и
  `PushTokenSource` на клиенте.
- Первая реализация — FCM. Подключается, когда владелец проекта предоставит
  Firebase-проект.
- Для разработки используется dev-реализация: логирование и локальное
  уведомление, без внешнего сервиса.
- Таблица `devices` хранит `push_provider` вместе с `push_token`, поэтому
  одновременная работа нескольких провайдеров (FCM, HMS, собственный) не
  требует изменения схемы.
- **Payload не содержит текста сообщения по умолчанию.** Передаются только
  идентификаторы; текст подгружается приложением после восстановления сессии.
  Показ текста включается пользователем явно в настройках (по умолчанию
  выключено — закреплено тестом `defaults are safe for privacy`).

## Последствия

- Отображение уведомления требует запроса к серверу — чуть медленнее,
  но не раскрывает переписку провайдеру.
- Пока FCM не подключён, push помечается в отчётах как «частично реализовано».
- Требуется корректная работа с разрешением `POST_NOTIFICATIONS` на Android 13+.

## Реализация (Этап 6b, 2026-11-13)

- Сервер: `PushProvider` с реализациями `FcmPushProvider` (HTTP v1; JWT
  сервисного аккаунта подписывается средствами JDK, без клиентской
  библиотеки Google) и `LoggingPushProvider` (нет ключа — запись в журнал).
- Push отправляется после фиксации изменения обёрткой над шиной событий
  (`PushingEventBus`) — на том экземпляре, где изменение произошло,
  поэтому ровно один раз.
- Payload — только `type` и идентификаторы. Устройство синхронизируется
  через журнал и показывает уведомление из локальной базы.
- Получатели — только устройства с живой сессией: выход, смена пароля и
  отзыв сессии прекращают push без участия клиента. Токен, который FCM
  назвал недействительным, снимается сразу.
- Напоминания о задачах — планировщик раз в 30 секунд забирает
  наступившие (`FOR UPDATE SKIP LOCKED`, отметка `reminded_at`).
  Напоминание получают исполнители, без исполнителей — автор.
- Android: Firebase подключается только при наличии
  `google-services.json`; без него приложение собирается и работает.
- Провайдеры HMS и DEV в схеме оставлены, но не реализованы.
