# Mango Messenger — архитектура

Mango Messenger — мессенджер для Android с интегрированным управлением
задачами: задачу можно создать прямо из сообщения, и она сохраняет связь
с исходной перепиской.

Продукт независимый: собственный код, схема данных, дизайн, название и
логотип.

---

## 1. Принципы

| Принцип | Что это означает на практике |
|---|---|
| Android-first | Клиент ведёт продуктовые решения; backend обслуживает его потребности |
| Offline-first | Room — источник истины, запись всегда локальная + очередь |
| Clean Architecture | domain не знает ни про Android, ни про Retrofit, ни про Room |
| MVVM + MVI | Состояние живёт в ViewModel, меняется целым неизменяемым объектом |
| Модульность | 10 core- и 8 feature-модулей; feature не зависят друг от друга |
| Честность статуса | Готовое, частично готовое и запланированное разделяются явно |

## 2. Слои Android-приложения

```
┌──────────────────────────────────────────────────────────┐
│ presentation                                             │
│   Compose UI  ──intent──►  ViewModel (MVI)               │
│       ▲                        │                         │
│       └── StateFlow<UiState> ◄─┘                         │
└───────────────────────────┬──────────────────────────────┘
                            │ только domain-модели
┌───────────────────────────▼──────────────────────────────┐
│ domain                                                   │
│   модели, интерфейсы репозиториев, use case              │
│   чистый Kotlin, без Android                             │
└───────────────────────────┬──────────────────────────────┘
                            │
┌───────────────────────────▼──────────────────────────────┐
│ data                                                     │
│   реализации репозиториев, мапперы                       │
│   Room  ·  Retrofit/WebSocket  ·  outbox  ·  sync        │
└──────────────────────────────────────────────────────────┘
```

### Жёсткие правила

1. **Compose UI не видит** Retrofit, Room DAO и DTO — только domain-модели
   и `UiState`.
2. **Room — единственный источник истины** для интерфейса. Сеть пишет
   в Room, UI читает из Room.
3. **Запись всегда через очередь**: локальное изменение + операция в
   `outbox_operations`, одной транзакцией.
4. `:core:model` и `:core:common` — **чистый Kotlin/JVM** без Android.
   Их тесты выполняются за миллисекунды и не требуют Robolectric.

Модули `:core:network`, `:core:sync`, `:core:realtime` и `:feature:*`
**намеренно не созданы пустыми**. Они появятся вместе с содержимым: каталог
из пустых классов создаёт ложное впечатление готовности.

Сейчас экраны живут в `:app`; при переходе к Этапу 4 они выносятся в
feature-модули вместе с реализацией.

## 4. Backend

Модульный монолит на Ktor — см. [ADR-0001](../adr/0001-modular-monolith-backend.md).

```
backend/
├── app/            точка входа, DI, роутинг, конфигурация
├── common/         ошибки, валидация, идентификаторы, время
├── auth/           регистрация, JWT, refresh, сессии, устройства
├── messaging/      чаты, сообщения, реакции, вложения
├── tasks/          задачи, исполнители, комментарии, события
├── realtime/       WebSocket-хаб, присутствие, fan-out через Redis
├── sync/           журнал событий, курсоры, идемпотентность
├── notifications/  рассылка push, абстракция провайдера
└── storage/        S3-совместимый клиент (MinIO локально)
```

Модули общаются только через публичные интерфейсы сервисов. Прямое
обращение к таблицам чужого модуля запрещено — это и есть будущая граница
отдельного сервиса.

Статус: **запланировано, Этап 3.**

## 5. Безопасность — краткая сводка

Подробно: [security-plan.md](security-plan.md).

- TLS для всего трафика.
- Проверка полномочий **на сервере в каждом запросе**: доступ к сообщению,
  задаче и вложению проверяется через членство в чате, а не через
  непредсказуемость идентификатора.
- `Idempotency-Key` против повторного применения операций.
- Rate limiting и защита от перебора паролей.
- Токены зашифрованы ключом Android Keystore
  ([ADR-0008](../adr/0008-token-storage.md)).
- Персональные данные редактируются перед записью в лог (`Redact`).
- Резервное копирование данных приложения отключено.
- **Сквозное шифрование не используется и не заявляется**
  ([ADR-0009](../adr/0009-no-e2ee-claims.md)).

## 6. Производительность

Целевые свойства: плавный скролл длинных переписок, отсутствие работы в
главном потоке, минимум лишних рекомпозиций, экономная фоновая синхронизация.

**Ни один показатель производительности сейчас не измерен.** В окружении нет
ни устройства, ни эмулятора, поэтому Macrobenchmark и Baseline Profiles
запустить невозможно. Любые утверждения о достигнутых показателях появятся
только вместе с результатами измерений.

Что уже сделано на уровне решений, а не измерений:

- `stateIn(WhileSubscribed(5_000))` — переживает поворот экрана без
  перезапроса;
- стабильные ключи в `LazyColumn`;
- `BoxWithConstraints` заменён на `Box` в аватаре — subcomposition на каждый
  элемент списка чатов был лишним (нашёл lint);
- список чатов собирается **одним SQL-запросом** вместо N+1;
- WAL-режим в Room: фоновая запись не блокирует чтение при скролле;
- пагинация по `seq`, без `OFFSET`.
